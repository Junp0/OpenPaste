## 自动测试

在仓库根目录运行：

```sh
./scripts/test.sh
swift build -c release
```

测试使用 Swift Testing，不依赖 XCTest。脚本在当前工具链存在对应文件时显式加载 `libTestingMacros.dylib`，处理部分 CLT / SwiftBuild 配置切换时的插件发现问题。

数据库测试使用临时目录；剪贴板测试使用命名测试剪贴板；交互测试使用隔离窗口、偏好设置套件或临时状态，不在普通剪贴板及真实历史上进行删除测试。

| 测试模块 | 覆盖范围 |
| --- | --- |
| ClipboardCoreTests | 原始格式往返、去重、清理、分组迁移、最近使用排序 |
| ClipShelfTests | 内容捕获、隐私标记、大小限制、搜索、分组、快捷键、预览及删除路由、命名输入、拖拽状态、显示大小与滚动指示 |

签名相关改动还需构建 `.app` 后执行：

```sh
./scripts/build.sh
./scripts/test-signing.sh
```

签名测试复制应用到临时目录，检查不同内容版本的 designated requirement 一致、相互验证身份，以及错误配置和同 Bundle ID 临时签名无法冒用身份。它不能替代真实辅助功能授权跨更新验证。

## 后台 30 MiB 目标

2026-11-06，0.6.0（构建号 16），Apple Silicon，Swift 6.4 / macOS 27 SDK：

- 保留原有 SwiftUI 界面，常驻进程只调度监测、菜单栏和全局快捷键。界面及捕获任务按需启动并在结束后退出；后台预算统计所有存活 OpenPaste 进程，不能只观察主进程而遗漏任务进程。
- 最终构建以 `--background --verify-background-memory` 启动，通过真实匿名管道加载并关闭隐藏的面板与设置。界面进程已正常退出，随后两次整进程采样分别为 **13.5 MiB、13.4 MiB**，均只有一个存活主进程。
- 用户在解锁状态确认了按需界面的显示、搜索、收起和快捷键再次唤起。当前界面工具按应用绑定，不能单独选中同一应用的界面进程；最终原生生命周期检查不显示窗口、不激活应用，在锁屏状态完成。
- 自动测试通过：数据库 9 项、应用 81 项，共 90 项。覆盖匿名管道分帧、同步响应、断连、快捷键超时撤销、恢复剪贴板前的确认、后台捕获、暂停期间不补录、敏感内容过滤、自身进程排除及原格式 / 指纹兼容。
- release 构建和严格签名校验通过，最终应用及压缩包位于 `release/`。这些结果不代表 Intel 或旧系统已经完成实际验证。

只读测量当前全部 OpenPaste 进程：

```sh
./scripts/measure-runtime-memory.sh
```

使用当前 release 可执行文件、隔离的命名剪贴板和临时数据库验证大内容捕获，原始剪贴板与用户历史不被修改：

```sh
./scripts/measure-capture-memory.sh
```

本机一次测量：1 MiB、18 MiB 文本成功保存，21 MiB 内容按上限跳过，所有捕获任务均正常退出。对应捕获任务的峰值 footprint 约为 16.9、161.2、45.4 MiB。**30 MiB 是后台空闲目标，不是窗口打开或捕获中的瞬时峰值上限。** 系统数据缓存被限制在任务进程内，任务退出后释放；常驻进程不读取这些载荷。

## 常驻内存与窗口释放

2026-11-06，0.6.0（构建号 15），Apple Silicon，Swift 6.4 / macOS 27 SDK：

- 面板收起后关闭并释放 NSPanel、内容界面及窗口资源，下次唤起按需重建；快速重新唤起时沿用过渡代数检查，避免旧的隐藏回调关闭新面板。
- 设置窗口关闭时释放 hosting view 和文本编辑器，并移除应用持有的窗口引用，停止已关闭设置界面的定时刷新。
- 所有业务窗口关闭一秒后，在 utility 队列调用系统公开的 `malloc_zone_pressure_relief` 回收未使用的分配器内存页；重新打开窗口会取消尚未执行的回收，不在剪贴板轮询中回收。
- 自动测试通过：数据库 9 项、应用 65 项，共 74 项。新增真实设置界面及面板连续三次关闭、销毁的回归，使用弱引用检查窗口、hosting view 与搜索输入框释放。
- release 编译、应用严格签名校验及 ZIP 完整性检查通过，产物位于 `release/OpenPaste.app` 和 `release/OpenPaste-0.6.0.zip`。
- 已解锁后分别重新启动旧构建 14 和新构建 15，使用同一份 35 条历史、同一显示尺寸，测量 `vmmap -summary` 的整进程 physical footprint；没有使用 RSS 或下方列表加载基准替代整进程数据。
- 实际验证了设置打开与关闭、面板销毁后的重新唤起、重建后的搜索；当前运行的开发应用及 `release` 产物均已更新为构建 15。

本机整进程单次对照结果：

| 状态 | 旧构建 14 | 新构建 15 |
| --- | --- | --- |
| 首次启动并显示面板 | 72.3 MiB | 68.6 MiB |
| 打开并关闭设置、收起面板后 | 85.7 MiB | 59.5 MiB |

新构建再次唤起、搜索并收起后为 62.9 MiB。主要改善发生在所有窗口关闭后的后台状态，不能据此承诺面板显示时低于 60 MiB；首次显示的少量差异可能包含系统缓存和采样波动。以上是当前机器和数据的一次运行结果，不代表长期上限。实际快捷键快速连续开关、多屏幕和旧系统仍需继续验证。

## 内存优化验证

2026-11-06，Apple Silicon，Swift 6.4 / macOS 27 SDK：

- 自动测试通过：数据库 9 项、应用 63 项，共 72 项。新增缩略图按需读取、缓存复用与释放、损坏图片、大图预览尺寸限制及原图无损恢复测试。
- 原生隐藏窗口测试连续三次销毁并重建真实 ShelfView，确认旧 hosting view 和搜索输入框释放，重新打开后滚动位置、选择和搜索控件正常。
- release 打包及严格签名校验通过，已重新启动本机开发应用；实际界面验证了收起、重新唤起及重建后的搜索。
- 图片预览最大边为 1400 像素；4096 × 3072 测试图片的预览为 1400 × 1050，命名测试剪贴板恢复的 PNG 字节与原图一致。
- 缩略图缓存设置 8 MiB 成本预算及 24 张数量限制，卡片离开视口时释放自身图片状态，面板隐藏动画结束后销毁界面并清空缓存。

可运行隔离基准：

```sh
./scripts/measure-history-memory.sh
```

脚本生成 1,000 条记录，每条含 128 KiB 不同的随机缩略图字节，在独立 release 进程中比较原先的全量加载与按需加载。临时数据库在结束后删除，不访问用户历史。使用随机字节模拟压缩图片数据，本基准不做图片解码或界面渲染。

本机一次测量的峰值内存 footprint：全量加载 129.3 MiB，列表元数据加载 11.3 MiB；记录数组持有的缩略图字节从 125 MiB 降为 0。该结果只反映历史列表加载，不能视作整应用内存降幅。实际界面、图片解码、系统缓存及文本历史仍会占用内存；真实长期使用和其他系统版本需另行测量。

## 手动验证范围

自动检查不能覆盖以下行为。涉及相应改动时，使用虚构内容验证并记录系统版本、架构、目标应用及授权状态：

- 菜单栏启动、全局快捷键唤起 / 收起、原应用焦点恢复。
- 文本、链接、图片及文件引用的记录、搜索、预览和粘贴。
- 搜索编辑、中文输入法组合、删除保护、删除后的相邻选择。
- 收藏与分组、拖拽归类、分组命名与图标。
- 三档显示大小、浅色 / 深色、减少透明度 / 减少动态效果。
- 首次辅助功能授权、已授权后的自动粘贴、保持签名身份后的更新。
- 登录启动、多显示器、全屏空间、小屏幕与不同缩放比例。
